节点地址变化后，旧配置可能继续指向失效主机、旧端口或不再接受的凭据。先确认官方是否发布变更，再区分订阅未更新、DNS 缓存与协议参数变化。

## 地址变化不只有换 IP

Endpoint 是客户端连接的远端入口，通常包含主机名与端口。服务商可能迁移入口、替换证书或轮换认证信息。域名没有变化也可能指向新的 IP；节点显示名称相同，不代表底层连接字段未改。

## 核对两份配置的来源

保留最后可用配置的时间，在服务商自己的面板获取当前适用格式。不要从搜索广告或转发链接获取所谓最新地址。比较主机名、端口、协议与必要认证字段时在本地进行；截图和客服记录都要去除秘密。

## 按症状判断更新位置

| 观察 | 优先核对 |
| --- | --- |
| 官方说明迁移，旧入口无法连接 | 当前订阅是否已成功更新 |
| 新旧主机名相同，部分设备仍异常 | DNS 结果、缓存及地址族 |
| 新入口可达但认证失败 | 账户状态和当前凭据 |
| 更新后客户端拒绝解析 | 格式与内核版本 |

不要把所有失败都解释为地址过期。

## 一次迁移示例

假设旧配置连接 node-old.example:443，新面板变为 node-new.example:8443。只手动改主机名而保留旧端口，可能仍然失败；完整重新导入官方配置更易保持参数一致。示例域名不是真实服务入口，不应粘贴为可用节点。

## 怎样避免覆盖后无法返回

先把旧文件加日期保存到受控目录，另建新档案测试，不直接替换唯一备份。确认新档案能完成真实任务后，再将其设为常用。旧凭据若已撤销，恢复旧文件也不能恢复权限；回退只针对本地误改，不是绕过服务商变更。

## 恢复后的验收项目

检查订阅更新时间、当前实际端点、握手或连接日志、流量收发和目标任务。若仍失败，向支持人员提供迁移前后字段差异的脱敏版本。域名、端口和证书要一起解释，不能建议用户随意关闭 TLS 校验。

## 补充核对细节

还要核对旧配置是否被本地固定地址、缓存副本或自动启动项再次加载。给测试档案加清楚的版本标记，并确认当前启用的确实是新档案。若电脑更新成功而路由器仍使用旧配置，应分别维护两端，不把一台设备的更新时间当成全家设备已经同步。

## 常见问题

### 节点名称没变还需要更新吗？

可能需要。名称是展示标签，入口和凭据可以独立变化。

### 把域名固定为某个 IP 更稳定吗？

未必。固定 IP 可能错过负载调整，并影响依赖主机名的 TLS 配置。
