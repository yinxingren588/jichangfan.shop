可用节点清单应记录“在哪些条件下完成了什么任务”，并保留失败与更新时间。它是一份个人运维记录，不是把所有节点永久贴上好或坏的标签。

## 先定义可用的验收标准

为网页、会议和大文件分别写成功条件，例如页面登录完成、会议共享可操作、下载校验通过。节点探测成功只说明探测请求有回应。固定标准后，下一次测试才能与过去比较，也能发现某条线路只适合部分任务。

## 清单至少包含这些字段

| 字段 | 用途 |
| --- | --- |
| 供应商与配置日期 | 防止混淆旧订阅 |
| 本地别名与实际节点名 | 订阅重命名后能继续追溯 |
| 接入、设备和客户端版本 | 解释环境差异 |
| 任务与结果时间 | 指明验证范围 |
| 失败表现和恢复办法 | 下次直接定位 |
| 倍率及来源 | 估算使用成本 |

不在清单保存密码或完整订阅 URL。

## 主用与备用怎样安排

主用选择最近满足核心任务的候选；备用最好具有可解释的差异，例如不同入口或协议。是否独立上游无法确认时应注明。备用至少实际连过一次，不能只因延迟显示绿色就视为完成切换演练。

## 一次清单更新示例

假设“办公主用”白天能下载但晚间会议断续，就保留原记录，新增晚间失败样本，并将会议备用临时提升。不要覆盖成简单的“不可用”。若官方订阅迁移，给新配置建立新记录，旧条目保留日期以解释变化。

## 多久复核一次更合理

在订阅更新、客户端升级、出差换网络或核心任务变化后复核。日常只需检查主备是否仍符合任务，不必无节制地测试全部节点。探测会消耗请求与流量；测试频率应配合服务商说明和自己的使用需求。

## 怎样防止记录变成秘密集合

用不含账号的别名，公开截图去掉端点、令牌、完整 IP 和设备识别信息。需分享配置时另建脱敏副本。清单同步前核对访问权限，离职或不再使用服务时删除不必要副本；订阅凭据泄露后应在服务商处重置。

## 常见问题

### 可以按一次测速给节点打长期分数吗？

不宜。时段、目标和接入变化会改变结果，分数应明确采样范围。

### 备用与主用同一个出口可以吗？

可以作为候选，但不能据此宣称独立容灾；还要看入口和供应商说明。
