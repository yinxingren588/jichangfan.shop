网页打不开时，先分开验证域名是否解析、连接是否建立、TLS 是否完成以及服务器是否返回响应。解析出 IP 只完成了其中一层，不能证明 VPN 路径和目标服务都正常。

## 从错误阶段开始分类

“找不到服务器”倾向于解析阶段；连接超时可能发生在路由、防火墙或服务端；证书错误通常属于 TLS 或时间与信任链问题；收到 HTTP 403 则说明至少已到达某个能够回应的服务。浏览器文案并非严格诊断，需要结合日志确认。

## 先保留系统原状

记下出错域名、时间、是否仅一个浏览器失败，以及 VPN 当前模式。检查其他正常网站只用于对照，不要立刻同时替换系统 DNS、浏览器安全 DNS 和客户端 DNS。一次改多层，即使恢复也无法知道哪项生效。

## 最小检查顺序

1. 在同一客户端重试同一域名并记录完整错误。
2. 查看客户端对该连接的解析、规则命中和上游连接记录。
3. 用产品官方允许的方法单独检查解析结果。
4. 若域名有结果但仍超时，转查连接路径和目标可用性；若仅浏览器异常，核对它自己的代理与 DNS 策略。

## 怎样读不同观察

| 现象 | 下一步 |
| --- | --- |
| 没有可用的 A 或 AAAA 结果 | 检查所用解析器、域名状态及 DNS 配置 |
| 有结果但连接超时 | 核对 IPv4/IPv6、路由和目标端口 |
| TLS 报错 | 核对域名、系统时间和证书链 |
| 返回明确 HTTP 错误 | 查看目标服务的访问条件与状态 |

这些是排查方向，不是根据一行错误就定责。

## 一个需要避免的 IP 测试误区

假设 example.com 已解析出地址，直接在浏览器输入这个 IP 后出现证书警告，并不能证明原域名被错误解析。HTTPS 往往依赖域名进行证书校验和虚拟主机选择。应保留原始主机名，按工具官方方法检查连接，不能关闭证书验证来制造“成功”。

## 恢复后怎样确认

若只恢复客户端 DNS 默认值后正常，重新建立连接并复测受影响域名与一个对照域名。记录恢复前后差异，必要时等待缓存失效。企业内网域名可能必须使用单位解析器，个人公共 DNS 不一定能解析，修改前先核对管理要求。

## 常见问题

### 能解析到 IP 就说明 DNS 没问题吗？

只能说明获得了结果；还可能涉及旧记录、不同地址族和不同应用使用不同解析器。

### 清空缓存可以解决所有打不开吗？

不可以。路由、端口、证书或服务端拒绝都需要各自处理。
