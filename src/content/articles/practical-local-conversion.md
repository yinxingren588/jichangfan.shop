订阅转换不一定需要把链接交给在线网站。先核对服务商是否提供目标格式、客户端是否能直接导入，再判断是否确实需要可信的本地转换工具。转换也无法让不支持的协议自动获得支持。

## 格式与能力是两件事

订阅可能是节点集合、完整配置、单节点 URI 或 VPN 档案。转换主要改变表达格式；原客户端专有的规则、DNS、脚本和传输参数未必能等价迁移。目标程序是否具备相应协议和功能，需要单独查官方兼容说明。

## 先按这个优先顺序选择

优先使用服务商针对目标客户端提供的入口；其次尝试目标客户端官方支持的直接导入；只有确有差异时，再评估可信工具。不要仅因别人推荐转换网址就提交带 token 的链接，在线服务可能能够获得和保存整份连接凭据。

## 转换前逐项列出差异

| 内容 | 核对要点 |
| --- | --- |
| 节点 | 协议、TLS 与传输字段是否保留 |
| 分流 | 语法、顺序与策略引用 |
| DNS | 是否由目标客户端重新生成 |
| 更新 | 转换后还能否按官方方式刷新 |
| 秘密 | 令牌和私钥在哪一环出现 |

无法确认的功能标记待验证。

## 本地转换也要核查来源

本地运行减少向远端提交秘密的机会，但不等于工具自动可信。核对项目维护者、发布来源、所需权限与网络行为；不要执行不明脚本或把配置写入公开日志。本文不要求安装任何转换程序，具体操作只应采用所选工具的官方方法。

## 一个无法等价迁移的例子

假设目标格式能表达节点，但不支持原配置的按进程分流。转换后节点可连接，不代表应用规则仍生效。应先用最小配置验证连接，再按目标官方支持方式重建需要的规则；无法实现时如实保留限制，而非生成看似完整的空规则。

## 失败后的恢复办法

保留原始配置与最后可用客户端，转换文件另存，不覆盖唯一备份。对照节点数量、认证和任务结果；若出现丢字段或订阅刷新失效，停止使用该输出并恢复原档案。曾交给不明服务的秘密按外泄处理，向服务商重置。

## 常见问题

### Base64 编码能保护订阅秘密吗？

不能。编码不等于加密，拿到内容的人通常可以还原。

### 转换后节点变少是否正常？

可能是过滤或不支持，也可能丢失数据；需要逐项核对，不能默认成功。
